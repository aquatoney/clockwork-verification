# Execution model and proof contracts

This document specifies the executable semantics added to the recursive compiler
model. The theorem names, hypotheses, and executable definitions are the source
of truth. The model concerns resolved core IR, rather than arbitrary C++ effects.

## State and external inputs

`Machine Value` contains a model store (`Nat -> Value`), per-domain queued and
admitted events, batch and partition reduction buffers, global aggregate values,
a resolved plan, outgoing/delivered events, published frontiers, synchronization
signals, and a scheduler step counter. Natural keys represent resolved state
region/key pairs. `Context` supplies a domain owner, window, safe time, and the
domains participating in the current reduction scope.

`Runtime Value` is deterministic and supplies:

- A reduction algebra with identity, associativity, and commutativity proofs.
- Resolved action instances for each execution call. `realizes` proves an
  occurrence-preserving permutation between the declared accesses and those
  actions. `serialRealizes` retains access order for sequential calls.
- Actual `Handler` values, whose `frame` and `locality` proof fields ensure that
  every store read/write effect relevant to reordering is covered. Emitted model
  effects must be represented in that store/contract, not hidden side effects.
- Transform effects, the post-handler `commit` that materializes emitted effects
  and consumes admitted work, resolved-plan reassignment, Choice guards, loop
  continuation, and per-domain window/safe-time resolution. `commitStore` proves
  that materialization does not change the model store after handler execution.

Callables can depend on the current machine state. The two compared modes invoke
the same callable on equal inputs, so later branches and loop choices agree.
The compiler does not synthesize a truthful binding or verify arbitrary external
code: an implementation must realize this interface and obey the paper's
binding contracts. In particular, materialization/reassignment must conserve
model events as intended and respect ownership; transforms must implement their
declared effects and domain-entry commutation contract. These are distinct from
the unconditional, local queue and routing conservation lemmas.

An `Access` occurrence represents one resolved modeled handler step. A step may
summarize a serial lane only if its effect contract covers the whole lane. A
single access entry does not authorize an arbitrary number of independent
invocations. `Permutation` is generated by identity, adding the same head,
adjacent swaps, and transitivity. `permutation_count` proves access multiplicity
preservation, not merely set membership.

## Recursive operational rules

`evaluate runtime mode fuel code context state` returns `Option ExecutionState`.
Fuel measures derivation height, not elapsed simulation time. At zero fuel it
returns `none`; invalid IR also returns `none`. No termination or completed
horizon claim follows from this convention. Nonempty successful executions are
checked in `Examples.lean`.

| IR constructor | Operational meaning |
|---|---|
| `stop` | Return the current state. |
| `invalid` | No successful execution. |
| `drain bound` | Resolve literal bounds directly and `.effective` to `min(window, safe)`; split the current domain queue and append newly admitted events to its existing admitted buffer. |
| `execute parallel group` | Instantiate the declared occurrences, run their store effects, then call deterministic materialization; record the requested call. |
| `transform fn` | Invoke the binding transform with current context/state. |
| `reduceBatch region` | Consume the owner's batch contributions and append their fold to partition partials. |
| `reducePair region` | Perform the batch fold, then compress partition partials to a single folded value. |
| `seq a b` | Evaluate `a`, then pass its result to `b`. |
| `branch guard a b` | Evaluate the guard against the current state and take the selected arm. |
| `loop body` | Stop when the continuation guard is false; otherwise execute `body` and unfold the loop with smaller fuel. |
| `domain plan effects admission body boundary tail` | Install the resolved plan; visit owner indices in `range plan.length`, resolve their contexts, admit their queues, run their bodies, and execute their boundaries; then execute the enclosing epilogue once. `effects` is a declaration, not a computed body summary. |
| `entry fn ...` | Run the transform in the outer context, then evaluate the domain. Accepted normal forms have no such unresolved entry. |
| `reassign plan` | Invoke the reassignment callable and install the resolved plan. |

A `routeAnnounce` boundary first appends intact outgoing events to the delivered
buffer according to the current plan, then writes its evaluated frontier. The
opposite boundary order is also defined, so normalization has a meaningful
operational consequence. `routeOutputs` uses `locateOwner`; unknown event nodes
are outside the valid-binding contract. Existence of owners for known nodes in
compiled plans is proved separately.

Epilogues record barriers and perform global folds over the enclosing domain
indices. Global folds consume those partition partials. These are serial
operational rules for the abstract IR; a recorded barrier does not mechanize a
concurrent barrier protocol, and publishing a frontier does not prove all local
successor work has completed.

Queues contain existing events. The deterministic `commit` and external
callables supply the event-generation/materialization behavior. Delivery to the
`delivered` buffer is concrete; scheduling that mail into future domain queues
is part of the runtime contract. The semantics does not independently generate
a reference event set or prove that every admitted event produces exactly one
modeled action.

## Two different reference results

`scheduled` executes the requested action order. `serialGroups` sorts each
parallel call by `Action.priority`; it retains sequential-call order and the
order of distinct calls. Both retain the *requested* calls as audit metadata.
Thus audit metadata in `serialGroups` is not a log of its sorted execution
order; `handlerTrace` represents the actual requested order for `scheduled`.

`evaluate_reference` derives equal complete interpreter results from `RaceFree`.
`compiled_execution_reference` obtains this fact from a successful Core compile;
`dsl_execution_reference` obtains it from DSL compilation. Proofs descend through
actual recursive semantics, including state-dependent control flow. They use
the proved independence of each actual action group, not an assumed
`ConflictOrdered` on a whole run. Equality concerns the same normalized program
in these two execution modes, with the same runtime inputs and fuel.

A globally priority-sorted handler trace is a separate result.
`evaluate_calls_safe` derives group independence for all dynamically recorded
parallel calls of a successful execution. `compiled_handler_trace_reference`
then uses:

1. `SerialCallsSorted`: every sequential call is internally priority-sorted.
2. `CallsChronological`: all priorities in an earlier call are no greater than
   all priorities in every later call.

The second is a sufficient order-band contract, stronger than the minimal
requirement to retain only conflicting-pair order. It is an explicit runtime
condition, not inferred by validation. Within each parallel call no priority
order is required. These conditions and compiler-established group safety imply
`ConflictOrdered`, which feeds the original `reference_equivalence` theorem.
The theorem compares the handler subtrace on any initial store. It does not
silently erase intervening transform/reduction/callable store effects to claim
an equality for the final state of arbitrary programs. The complete-state
result above instead retains all such effects in their structured order.

Priority must encode a fixed timestamp/reference tie order of the finite
modeled actions. It cannot be assigned after choosing the execution order.
Insertion sort retains input order at equal priorities; a particular global tie
policy must therefore be represented faithfully in the priorities/contracts.

`Examples.lean` checks an accepted pair of individually safe calls whose
concatenated trace disagrees with its sorted reference. This explains why an
unconditional globally sorted equivalence theorem would be false for the current
compiler model, and why the two reference results must remain distinct.

## Admission, boundary, reduction, and ownership connections

`admissionSites` includes explicit drains and implicit domain admission, across
both branches, loops, and nested domain scopes. Successful compilation forces
every spatial occurrence to use `.effective`. The interpreter uses the same
`evalBound` and `Clockwork.drain` referenced by `compiled_drain_safe`.
`compiled_admit_safe` also accounts for previously admitted work; conservation
holds even for repeated admission because that work is appended to, not erased.

`compiled_admission_no_unseen_predecessor` combines the compiled bound with
`safeFrom` and `unseen_after_safe`. For an incoming edge, work through its
frontier must have completed; an unseen producer is strictly after that frontier
and its arrival obeys the declared lookahead. The resulting strict separation
rules out an unseen remote predecessor of admitted work. This theorem does not
assume a generic availability predicate as its conclusion in disguise.
An earliest-unprocessed-event bound is different: inclusive admission there
requires the separate FIFO endpoint/reference-tie condition. Its connection to
actual C++ paths remains implementation evidence, not a new compiler theorem.

`compiled_domain_contract` follows recursive `Subcode` containment to extract
boundary order, the exact required reduction epilogue, and ownership from
pipeline invariants. `compiled_boundary_signals` proves the concrete signal
order and evaluated announcement bound. `compiled_boundary_conserves_outputs`
connects the boundary implementation to event preservation.
`compiled_domain_has_owner` proves an actual `locateOwner` result for every
known model node in that domain plan. It does not prove that external callables
never create unknown nodes or corrupt the current plan.

The reduction lemmas apply to the concrete buffer/fold operations used by
`evaluate`. They preserve the corresponding folded values while consuming or
compressing contributions. The compiler supplies the hierarchical placement;
`three_level_reduction` supplies the identity for grouped contributions.
Generation of the intended contributions and consumption after synchronization
remain model/runtime contracts. Theorems do not prove arbitrary floating-point
addition associative; a chosen `Reduction` must satisfy the declared algebra.

## Explicit remaining boundary

The development checks the specified compiler and finite interpreter. It does
not mechanize C++ translation, arbitrary concurrent domain interleavings,
lookahead discovery, round completion, horizon progress, a transport protocol,
or equality of independently generated DES event sets. In particular,
cross-domain summary declarations are checked for compatibility, but their
coverage of actual dynamic body effects is a binding responsibility. Realizing
the finite model in the implementation is separate from the checked derivations.
Repair passes intentionally change unsafe IR behavior; no semantic-preservation
claim is made between unsafe raw IR and its repaired form.
